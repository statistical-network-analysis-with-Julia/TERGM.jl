# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

TERGM.jl is a Julia port of the R [tergm](https://cran.r-project.org/package=tergm) package from the StatNet suite, implementing Separable Temporal Exponential Random Graph Models (STERGMs) for statistical modeling of dynamic networks observed at discrete time points.

## Development Commands

- **Run tests:** `julia --project -e 'using Pkg; Pkg.test()'` (the suite is one flat `test/runtests.jl`; run a subset by filtering testsets, not files). `Pkg.test` sets `--depwarn=yes`, which the deprecation testsets rely on. One CI cell runs with `JULIA_NUM_THREADS=4`; the bootstrap/gof testsets assert thread-count independence, so run locally with `-t 4` too before touching either.
- **Build docs:** `julia --project=docs -e 'using Pkg; Pkg.instantiate()'` once, then `julia --project=docs docs/make.jl` (Documenter, **strict**: `warnonly = false`, `checkdocs = :exports` — every export needs a docstring and every `@ref` must resolve). `docs/Project.toml` sources `TERGM`, `ERGM` and `Networks` by path; its Manifest is gitignored.
- **Snippet check:** `SNWJ_ROOT=<root> julia --project=<root>/.snippet-env <site>/tools/check_snippets.jl TERGM.jl` executes every `julia` block in README.md and docs/src (the site's checker; the `ERGM.jl` path filter also matches this package). The s50 blocks fit a 50-actor, 3-wave panel with `gof(n_sim = 100)` in a few seconds.
- **Clean-depot install:** `julia <site>/tools/check_clean_depot.jl` from the site repo installs every package into an empty depot in dependency order (TERGM after Networks and ERGM) — the check that `Project.toml` compat and `[sources]` are right.
- **Regenerate the golden fixture:** `Rscript test/fixtures/r/panel_stergm.R > test/fixtures/panel_stergm.toml` (needs R with `tergm` ≥ 4.2 and `btergm`).

## Architecture

The entire package lives in a single file: `src/TERGM.jl`. It is organized into four sections:

1. **Temporal Term Types** -- `TemporalTerm <: AbstractERGMTerm` subtypes: `EdgeStability`, `Delrecip`, `PersistentEdge`, `NewEdge`. Each implements `compute(term, net, prev_net)` and `change_stat(term, net, i, j, prev_net)` (ADD-DIRECTION, state-independent; calling without prev_net raises an informative error). Standard ERGM.jl terms mix freely (dispatch via `_tchange`/`_tcompute`; `gof` evaluates the model statistics through `_tcompute`). The terms take part in ERGM.jl's **public term-trait protocol** — `is_dyad_dependent(::T) = false` for all four (they condition only on the exogenous previous network) and `requires_directed(::Delrecip) = true` — which is what lets ERGM's formula validation and `has_dyad_dependent` see them exactly as they see the built-in terms. `Delrecip` also guards its own `compute`/`change_stat`: on an undirected network it throws an `ArgumentError` (the same message shape as ERGM's `_undirected_only_message`) rather than returning a silent `0.0`. **`Delrecip` is the only temporal term a formula may carry.** It is btergm's `delrecip` (lag 1), *not* a tergm term — tergm ≥ 4 has no `InitErgmTerm.delrecip`, so no R fixture can pin it; its definition is pinned by hand. `EdgeStability`/`PersistentEdge`/`NewEdge` are **descriptives only**: on the free dyads of a separable model their change statistic is one constant per side (`_separable_constant(term, side)` returns the sentence), so `_validate_terms` refuses them in either formula with an `ArgumentError` naming the mechanism (rank-deficient beside `Edges()`, `edges` under another name without it; informative only in a non-separable btergm-style TERGM, which is not implemented). `gof` uses `NewEdge`/`PersistentEdge` for its formed/persisted counts. Tie-duration descriptives: `edge_ages`, `mean_edge_age`.
2. **STERGM Model Types** -- `STERGM` (formula holding formation/dissolution terms; each side goes through ERGM's `_collect_terms`, so a `push!`-built `Vector{Any}`, a bare term or nested vectors are accepted and a non-term is refused naming the side and position; `show` is one line), `STERGMModel{T,D}` (formula + observed panel as a concretely typed `Vector{Network{T,D}}`, mirroring `ERGM.ERGMModel{T,D}`; `is_directed(model)` is a `Graphs.is_directed` method returning `D`, and a panel of a different `Network{T,D}` is refused at construction; `show` is one line — panels, size, directedness, free dyads, both formulas' labels — never the panels), `STERGMResult{T,D}` (fitted coefficients, SEs, convergence info, `se_type` — `:hessian` or `:bootstrap` — and `boot_replicates`, the `n_boot × p` bootstrap refits; ONE 13-field positional constructor, no compat forms). The inner constructor of `STERGMModel` refuses, per panel and naming it: a **two-mode** panel (`is_two_mode`; the one-mode CMPLE would enumerate the impossible within-mode dyads), a panel with a **self-loop** (the statistics would count it, the free dyads/`nobs`/sampler never see it — ERGM.jl's `_refuse_two_mode`/`_refuse_self_loops` do the same, but their messages say "ERGM.jl", so TERGM states its own), and a **masked** panel (`require_observed`). **Formula validation is ERGM.jl's, not ours:** `_validate_terms` calls the `public` `ERGM._validate_formula(TermSet(terms), net)` on **every** panel — the very function the `ERGMModel` constructor runs — and only prefixes the `ArgumentError` with the side and the panel (`formation model, panel 2: ...`). That buys, for free and identically to ERGM: missing-attribute refusal with the available attributes listed, NA-completeness (an attribute not set on every vertex is refused, naming the vertices), `requires_directed` (`Mutual`/`Delrecip` on undirected panels), `requires_undirected` (`Kstar`/`GWDegree`/`Degree` on directed panels, with `OStar`/`GWODegree`/`ODegree` named) and the `EdgeCov` size check. Never re-implement a check here; add it to ERGM — the one check that IS TERGM's (the memory-term constancy) exists only because a separable model has it. **Term expansion is ERGM.jl's too** (round 3): after validation the constructor runs the `public` `ERGM._materialize` on each side — the step `ERGMModel` runs — so a multi-level `NodeFactor(:grp)` becomes one statistic per non-base level, a multi-cell `NodeMix(:grp)` one per selected cell (statnet's cell order) and `Degree(0:2)`/`IDegree`/`ODegree` one per degree, under R's labels (`nodefactor.grp.b`, `mix.grp.a.b`, `degree1`). Before round 3 the raw terms were bound and `NodeFactor(:grp)` was fit as ONE pooled column labelled `nodefactor.grp` (the sum of R's columns) — a silently different model. Because ERGM's materialized twins snapshot the attribute of the ONE network they are given, while a STERGM evaluates its terms on T−1 auxiliary networks, `model.formula` stores the *specification* — the expansion as plain single-statistic terms (`_expand_side` → ERGM's `public` `_expand_terms(terms, net)`, the specification without the snapshot; TERGM's own `_specification`, which unwrapped a twin's `base` field from outside ERGM, is gone) — and every hot path snapshots per transition through `_materialized_tuple(terms, net)` against the auxiliary network the statistics are evaluated on (`_cmple_blocks` against Y⁺/Y⁻, `_sample_constrained` against Y_{t−1}, `_transition_stats!` against Y⁺/Y⁻). Levels are resolved from panel 1, which coincides with R's union-of-panels resolution exactly when no later panel carries a value panel 1 lacks — so `_expand_side` checks that (for every term whose `_materialize` returns a Vector, over its `required_vertex_attributes`): a level absent from a later panel is fine (all-zero column there, as in R), a new one is refused (`ArgumentError` naming side, panel and value). `simulate_stergm(prev, formula, θf, θd)` validates (`_validate_formula`) and expands (`_expand_formula`) against `prev` the same way. The dissolution model is fit in tergm's **persistence** (`Persist()`) parameterisation: the fields and accessors are `persistence_coef`/`persistence_se` (plus `formation_coef`/`formation_se`); `dissolution_coef`/`dissolution_se` are deprecated aliases (a `getproperty` shim and two functions with `Base.depwarn`) of the same numbers, and tergm's `Diss()` sign convention is deliberately not offered. `has_dyad_dependent(::STERGMModel)` is a method on ERGM's **exported** generic (there is no private `_has_dyad_dependent` any more); `show`, `is_exact` and `approximations` all dispatch on it, so the prose caveat and the machine-readable metadata cannot drift apart. Coefficient labels come from `_labels(terms, net) = [name(t, net) for t in terms]`, ERGM 0.2's direction-aware two-argument `name`, so a directed panel's `GWESP(0.5)` prints `gwesp.OTP.fixed.0.5` exactly as R and ERGM.jl do. **`show` and `coeftable` are the same numbers by construction:** `_side_tables(r)` builds one `Networks.CoefficientTable` per model (labels, `z = θ/se`, `p` through `_pvalues` so a `±Inf` coefficient prints `p = 0`); `show` renders them as the `Formation:` / `Persistence:` blocks through `print_coeftable` (header first: panels/transitions/free dyads, the pseudo-log-likelihoods, `AIC: …, BIC: …` as `ERGMResult`'s header has it, the standard-error method and replicate count, `Converged:` with the caveat sentence as `WARNING:` right there for an unconverged fit), and `StatsAPI.coeftable(r)` stacks them under tergm's `Form(1)~` / `Persist(1)~` prefixes. `StatsAPI.confint(r; level)` is the Wald interval from the SEs the fit reports. The **full StatsAPI surface** (`coef`, `stderror`, `vcov`, `confint`, `loglikelihood`, `nobs`, `dof`, `aic`, `bic`, `coeftable`) is defined on `STERGMResult`, every verb the ONE `StatsAPI` binding that Networks.jl/ERGM.jl re-export, and pinned by `Networks.check_statsapi(fit; strict=true)` in three testsets (Hessian, bootstrap, boundary fit).
3. **Estimation** -- `stergm()` defaults to `cmple()`: pooled logistic pseudo-likelihood over the FREE DYADS of the auxiliary networks (formation rows = prior non-edges with stats on Y⁺ = Y_{t−1} ∪ Y_t; dissolution rows = prior edges with stats on Y⁻ = Y_{t−1} ∩ Y_t; `formation_network`/`dissolution_network` expose the construction), maximized by ERGM.jl's `public` MPLE design fitter (`_mple_fit_design`, imported by name, called with `context="cmple"` so both R sentences carry TERGM's name) on the shared `Networks.newton_fit`/`logistic_derivatives` kernel — so a CMPLE fails exactly as `ERGM.mple` does and never silently: a statistic at the boundary of its attainable range is fixed at ∓Inf (SE 0, p 0) and the rest refit on the untouched free dyads (R ergm's `drop`; `dof` counts the finite coefficients, `bic` uses `n_kept`, `se=:bootstrap` is refused), a design separated by a combination of statistics is `converged=false` with R's "The MPLE does not exist!" warning, an exhausted `maxiter` and an empty side are warned about; every `converged=false` and every ∓Inf is listed by `approximations` and printed by `show`, and makes `is_exact` false. `se=` is validated by `Networks.check_se`. **The convergence verdict is scale-free, in the shared kernel:** `Networks.newton_fit` declares convergence on the Newton decrement `½·gᵀ(−H)⁻¹g < tol` beside the gradient norm, accepts a step whose log-likelihood decreases by rounding noise while the gradient shrinks, and takes the last full step at a stall whose predicted gain is below `tol` (the reconciliation round adopted it there from TERGM's round-2 request). Before that, a `Triangle` column running to 33 over 3 000 rows left the golden panel's triangle fit `converged == false` one Newton step short of the optimum where R's glm converged, and `_logistic_fit` carried a local `_polish_newton`; it is deleted, the `dyaddep_triangle` testset asserts `converged` and a vanishing gradient directly, and a fit stopped by the Newton cap still stays unconverged (the `maxiter=1` testset). Design rows are built per transition (`_cmple_blocks`: the block sizes are known up front — `ne(prev)` dissolution rows, the rest formation rows — so the four arrays of a transition are allocated once and filled in place through `_fill_blocks!`, a typed barrier over the two *materialized* term tuples (`_materialized_tuple` against Y⁺/Y⁻, so attribute terms read dense snapshots, never the attribute Dicts — a raw `NodeMatch` cost 160 B per row before round 3) with the statically unrolled `_fill_row!`; the build allocates what it returns plus the two auxiliary networks and a per-transition constant (plus one `Int` per vertex per attribute term for the snapshot), never per row — pinned by `@allocated` with `[Edges(), Mutual(), NodeMatch(:grp)]`) so `se=:bootstrap` can run a per-transition block bootstrap (btergm-style: resample transitions with replacement, refit, empirical covariance of the stacked coefficients; needs ≥ 2 transitions). **The bootstrap loop is `Networks.bootstrap_cov`** — the ONE shared resampling loop — and `_cmple_block_bootstrap` supplies only the two callbacks: `simulate(rng, B)` draws all `B` transition resamples up front from `rng` (in the order the pre-0.2 serial loop drew them, so the SEs are unchanged and the threaded refits are thread-count independent) and `refit(idx)` refits the CMPLE on one resample. A replicate with a non-finite refit is a NaN row of `boot_replicates`, excluded from the covariance, warned about once and listed by `approximations(fit)`. `cmle` throws an `ArgumentError` (MCMC CMLE is not implemented, and CMPLE is only the same estimator for dyad-independent terms, so it does not silently stand in). `egmme` raises an error instead of returning placeholders, and is **not exported** — an estimator that can only throw must not advertise itself in the public API; it stays reachable as `TERGM.egmme` so the error is informative rather than an `UndefVarError`, and `method=:egmme` still raises.
4. **Simulation & Diagnostics** -- `simulate_stergm()` samples Y⁺ (Metropolis over prior non-edges) and Y⁻ (over prior edges) and combines Y_t = (Y⁺ \\ Y_{t−1}) ∪ Y⁻. **The Metropolis loop is ERGM.jl's exported `mh_toggle!` kernel** (`_mh_constrained!`: a move is a dyad drawn uniformly from the `free` list, `change!` fills the temporal change statistics through the statically unrolled `_fill_delta!` over a term *tuple* — the materialized twins snapshotted from Y_{t−1} by `_materialized_tuple`, so an attribute term is 0 B per toggle (112 B through the Dict before round 3) — and returns whether the dyad is a tie, `apply!` toggles it, `n_samples=0` so the state after `burnin` toggles is the draw). The kernel consumes `rng` in the order the old hand loop did — proposal index, then one uniform — so the draws are bit-identical to pre-0.2 (pinned against a reference implementation of the old loop in the tests) and allocation-free per step (pinned by `@allocated`). `burnin` defaults to `nothing`, resolved per side by ERGM's `public` `_mcmc_defaults(n_free).burnin` (20 toggles per free dyad of that side). `simulate_network_sequence()` iterates and returns a `Vector{typeof(init_net)}`; `gof()` (a method on Networks.jl's shared generic — THE goodness-of-fit verb of the family; `stergm_gof` is a `Base.@deprecate`d forwarding method, removed next release) returns five `GOFStatistic` panels after `gof.tergm`, pooled over transitions, each with MC p-values: `"tie changes"` (formed/persisted — the sufficient statistics of `Form~edges`/`Persist~edges`, reproduced by construction, so a simulator sanity check only), `"formation statistics"`/`"persistence statistics"` (every formula term on the observed vs simulated Y⁺/Y⁻ via `_transition_stats!`/`_tcompute`, labelled by the coefficients — where a dyad-dependent CMPLE's misfit shows), and the degree distribution of Y_t (`"idegree"`+`"odegree"` directed, `"degree"` undirected; `_degree_counts!`). It draws one seed per (transition, simulation) from `rng` up front and runs the simulations under `Threads.@threads`, so it is reproducible from `rng` alone and thread-count independent (pinned against a serial reproduction of the seeding scheme).

The main entry point is `stergm(networks, formation_terms, dissolution_terms; method=:cmple)`.

## Cross-package hygiene

Every shared verb or rule is **imported by name** from the package that owns it — `import Networks: z_pvalues, check_se, bootstrap_cov, newton_fit, logistic_derivatives, gof, estimand, ...` and `import ERGM: name, compute, change_stat, is_dyad_dependent, has_dyad_dependent, requires_directed, mh_toggle!, TermSet, _validate_formula, _materialize, _mcmc_defaults`. The three `_`-prefixed names taken from ERGM.jl are declared `public` there. The "No private cross-package reach-ins" testset reads `src/TERGM.jl` as text (comments and docstrings stripped) and asserts that no `ERGM._x`/`Networks._x` dotted reach-in exists and that every `_`-name in an `import ERGM:`/`import Networks:` list is `Base.ispublic` where it lives; it also asserts the deprecated private aliases (`_z_pvalues`, `_requires_directed`, `_vertex_attribute`, `_has_dyad_dependent`) no longer appear. If ERGM or Networks makes a helper private again, that testset is what goes red. Its allow-list of `_`-names imported while a cross-repo `public` request was pending (`_mple_fit_design`, `_warn_boundary`, `_warn_separated`, `_collect_terms`) is empty since the reconciliation round declared them (`_warn_boundary`/`_warn_separated` are no longer imported at all: `_mple_fit_design(...; context="cmple")` emits both sentences); it now asserts every imported `_`-name public and that no `# cross-repo request pending` marker survives. Two-mode and self-loop refusal use only public Networks/Graphs API (`is_two_mode`, `has_edge`), stated in TERGM's own words rather than through ERGM's private `_refuse_*` (whose messages say "ERGM.jl").

## The three shared kernels are not ours (review finding 15; panel 2026-09 items 14, 24, 28)

**The CMPLE derivative loop is `Networks.logistic_derivatives`, driven by `Networks.newton_fit`, inside ERGM.jl's `_mple_fit_design`.** `_logistic_fit` used to carry its own copy of the logistic loop with `hess .-= (pr*(1-pr)) .* (x * x')` inside it: a fresh `p×p` outer product on every one of the design rows of every Newton evaluation — **471 KB and 0.46 ms per evaluation** on a 25-actor, 8-wave panel. The kernel moved to Networks.jl in 2026-09 (item 14; ERGM.jl re-exports the same binding, and ERGM's MPLE, ERGMMulti's MPLE and ERGMRank's swap MPLE run on it): workspaces allocated once, `η = Xβ` by gemv and `−H = X'WX` by gemm, **192 bytes and 0.11 ms per evaluation** — 4.0x faster, with allocations independent of the number of rows. `_logistic_fit` hands the Bernoulli-row design (`n_tot = 1`, `n_one = y`) to `ERGM._mple_fit_design`, which wraps that kernel in R ergm's attainable-range drop and separation detection — that is where the ∓Inf / `converged=false` semantics come from, and why they are identical to `ERGM.mple`'s. **Never paste the loop back in**; if it needs a feature, add it to `Networks.logistic_derivatives` or to ERGM's design fitter. The `@allocated` regression test measures the closure built from TERGM's own `_cmple_blocks` design rows (in the binomial-row form the fitter uses), so it guards this package's path and not just Networks' function. The summation order is BLAS's, so the arithmetic is not bit-identical to the old loop — but the *fit* is: measured on the same design, **max|Δθ| = 0.0**, and the golden fixture is unmoved at its 1e-6 exact-CMLE tolerance (TERGM.jl remains closer to the exact optimum than `tergm` itself).

**The bootstrap loop is `Networks.bootstrap_cov`.** `_cmple_block_bootstrap` was a hand-written serial loop beside the ecosystem's "ONE shared bootstrap" (panel item 28). It now supplies only the two callbacks: `simulate(rng, B)` draws every transition resample up front from `rng` in the order the old loop drew them, `refit(idx)` refits both sides on one resample with `warn=false` and returns a `NaN` row for an unconverged or `±Inf` refit (excluded from the covariance, warned about once, recorded in `boot_replicates` and `approximations`). The refits are deterministic per resample, so the threaded loop is thread-count independent. Measured on the golden 25-actor, 8-wave panel at `n_boot=400`: **0.307 s** (committed serial loop) → **0.314 s** on one thread → **0.114 s on four**, standard errors identical to 1e-15.

**The Metropolis loop is `ERGM.mh_toggle!`.** `_sample_constrained` was the fourth copy of the family's toggle skeleton (panel item 28; the term loop dispatched through a `Vector{AbstractERGMTerm}`, §6). It now builds the `free` list, resolves `burnin` (`_mcmc_defaults(n_free).burnin` unless given) and calls `_mh_constrained!`, a typed function barrier over the term *tuple* that hands the kernel three closures (`propose` = uniform draw from `free`; `change!` = `_fill_delta!`, a statically unrolled recursion over the tuple, returning whether the dyad is a tie; `apply!` = toggle). The kernel consumes `rng` exactly as the old loop did — proposal index, then one uniform — so the output is bit-identical: a draw taken with the committed loop is frozen as a literal edge list in the "Frozen pre-refactor sampler output" testset. Measured: **16 B per toggle before → 0 B per toggle** (pinned by `@allocated`: 2 000 toggles allocate exactly what 1 000 do — with an attribute term in the formula since round 3, where the raw `NodeMatch` had still cost 112 B per toggle).

## Golden fixtures (statnet tergm)

`test/fixtures/panel_stergm.toml`, generated by `test/fixtures/r/panel_stergm.R` and loaded with Networks.jl's `load_golden` (which throws without `[provenance]`). An 8-wave, 25-actor directed panel is frozen as edge lists, so both packages fit identical networks; the model is `Form(~edges + nodematch("grp")) + Persist(~edges + nodematch("grp"))` under `estimate="CMPLE"`.

The formulas are **dyad-independent on purpose**: the conditional pseudo-likelihood is then the conditional likelihood, CMPLE is the exact conditional MLE, and agreement can be asserted at 1e-6 instead of hand-waved. A dyad-dependent formula would have bought a prettier model and destroyed the ability to say anything exact.

**What it found — and it is R's slack, not ours.** `tergm`'s CMPLE runs R's `glm` at the default `epsilon = 1e-8` and stops **1.5e-8** (coefficients) / **6.1e-6** (standard errors) short of the exact optimum. TERGM.jl's Newton–Raphson lands *on* the optimum, reproducing a tightly-converged (`epsilon = 1e-14`) R `glm` to ~1e-10. So the fixture freezes **both**: `coefficients`/`std_errors` are tergm as shipped (SEs compared at 1e-4 — a tolerance that measures R), and `exact_coefficients`/`exact_std_errors` are the same estimator taken to convergence (compared at 1e-6 — the tolerance that measures Julia). The testset also asserts TERGM.jl is *closer to the exact optimum than tergm itself is*. Do not "fix" a red test here by loosening the exact tolerance.

**The boundary panel (`boundary_*` keys).** A second, 8-actor 3-wave panel in which no same-group tie ever persists, so `Persist~nodematch.grp` has no finite CMPLE. tergm 4.2.2 does *not* drop it (its operator terms bypass ergm's attainable-range check): it warns "The MPLE does not exist!" and returns a point on the asymptote (−19.57, SE 1621), which the fixture records but never asserts. What it asserts is what IS a number and identical in both packages: the three finite coefficients and their SEs (as shipped at 1e-6/1e-4 and at glm convergence at 1e-6 — measured slack 8e-16), the log-likelihood (1e-5; R's differs from the exact dropped limit by the asymptote's tail, −1.4e-7, frozen as `boundary_asymptote_tail`), R's `logLik` nobs, and the warning text. TERGM.jl reports −Inf with SE 0 there (R ergm's `drop=TRUE`), `dof` = 3 where tergm's df says 4 — the fixture documents the difference and the reason.

Block-bootstrap SEs are compared at the resolution the bootstrap actually has: the R script reruns btergm's transition-resampling scheme under five further seeds and freezes the seed-to-seed sd of every bootstrap SE, and the tolerance is a multiple of that. Two bootstraps drawing different resamples cannot be compared any other way.

**Dyad-dependent and undirected panels (`dyaddep_*`, `undirected_*` keys).** tergm's CMPLE for `mutual`/`triangle` and for undirected panels is the same estimator written by other people; until round 2 nothing pinned the evaluation of a dyad-dependent change statistic *on Y⁺/Y⁻* or the `n(n−1)/2` undirected free-dyad enumeration against R. Frozen as tergm ships them (glm at default epsilon) and compared at the main panel's as-shipped tolerances (1e-6 / 1e-4 / 1e-5 on loglik): `Form(~edges + mutual) + Persist(~edges + mutual)` and `Form(~edges + triangle) + Persist(~edges)` on the main directed panel; `Form(~edges + nodematch) + Persist(~edges + triangle)` and `Form(~edges + kstar(2)) + Persist(~edges)` on a frozen 14-actor 5-wave undirected panel (`undirected_loglik_nobs = 364`). Measured agreement ~1e-9. The testsets assert `fit.converged` and that R warned nothing — the triangle fit is the regression test for the shared kernel's scale-free convergence verdict (formerly TERGM's `_polish_newton`).

**Expanding terms (`expand_*` keys, round 3).** `undirected_grp3` puts a three-level attribute on the same frozen undirected panel; `expand_undirected` is `Form(~edges + nodefactor("grp3")) + Persist(~edges + nodemix("grp3"))` (9 coefficients), `expand_undirected_degree` `degree(1:2)` / `degree(0:1)`, `expand_directed` `nodefactor("grp")` / `nodemix("grp")` on the main panel (6: directed nodemix has cells b.a, a.b, b.b), `expand_directed_degree` `nodemix("grp")` / `odegree(0:1)`. `check_golden_fit` asserts the term names verbatim before any number, so a pooled or mislabelled expansion fails on the labels. All four are warning-free in R (`stopifnot` in the script) and compared at the as-shipped tolerances.

- **PrecompileTools.jl** -- the `@compile_workload` at the end of `src/TERGM.jl` (fit, show, bootstrap, simulate, gof on a 6-actor panel under a devnull logger); first `stergm` fit 1.6 s → 0.04 s

## Conventions

- All temporal terms subtype `TemporalTerm <: AbstractERGMTerm` and must implement `name()` and `compute(term, net, prev_net)`.
- Change statistics follow the ERGM.jl ADD-DIRECTION convention: `change_stat(term, net, i, j)` = g(y⁺ij) − g(y⁻ij), state-independent. Temporal variants take a trailing `prev_net` argument and obey the same convention (brute-force verified in tests).
- Formation terms operate on dyads that were non-edges at t-1; dissolution terms operate on dyads that were edges at t-1.
- The dissolution model estimates **persistence** (not dissolution) coefficients -- positive values mean higher persistence; the accessors are `persistence_coef`/`persistence_se`, and `dissolution_*` are deprecated aliases of the same numbers (never negate them: tergm's `Diss()` is not offered).
- All randomness flows through an `rng::AbstractRNG` keyword; sampler `burnin` defaults are dyad-scaled (`ERGM._mcmc_defaults`), never literals. Parallel loops (`bootstrap_cov`'s refits, `gof`'s simulations) draw everything random from `rng` up front — one resample or one seed per task — so results are thread-count independent.
- Keyword vocabulary is the root CLAUDE.md's: `maxiter`, `tol`, `n_sim`, `n_boot`, `burnin`, `rng` (never `max_iter`, `n_sims`, `seed`); pinned by a `Base.kwarg_decl` testset.
- One verb per job, owned elsewhere: `gof(fit)` (Networks), `coeftable`/`confint`/`coef`/… (StatsAPI, via Networks/ERGM). Never add a package-specific spelling (`stergm_gof` is the deprecated example); the "Shared verbs are single-owner" testset asserts binding identity and `Test.detect_ambiguities(TERGM, ERGM, Networks)` is empty, and `using ERGM, TERGM, SNA, REM` was verified to leave every verb single-owner.
- Deprecations are `Base.@deprecate` / `Base.depwarn` with the new name in the message, kept exported for one release, and tested with `@test_deprecated`/`@test_logs` — `Pkg.test` runs with `--depwarn=yes`, so a deprecation that stops warning is a red test, not a silent one. Current list: `stergm_gof`, `dissolution_coef`, `dissolution_se` (function and property forms).
- Missing-data vocabulary: no `missing=` keyword anywhere (`missing_policies(stergm) == (:error,)`, `supports_missing == false`), `require_observed(...; face_ok=false)` so the refusal never names `:face`; pinned in "Missing dyads are rejected".
- Teaching data: README/Getting Started/estimation guide fit `Networks.load_dataset(:s50)` (three directed waves, `:smoke` attribute set from wave 1); the synthetic toggled panel is kept only as "Building a panel by hand". Every block is run by the site's snippet checker.
- Nothing about a bad fit is silent: an unconverged, separated, empty-sided or boundary (`±Inf`) fit warns at fit time, is recorded in `approximations(fit)`, printed by `show`, and makes `is_exact(fit)` false.
- Not implemented, and documented as such with the exact error (README "Not implemented", docs `guide/estimation.md`): MCMC-based CMLE (`ArgumentError`), EGMME (`ErrorException`, unexported), masked-panel estimation (`STERGMModel` refuses, no `missing=` keyword), two-mode panels and self-loops (`STERGMModel` refuses, naming the panel), non-separable/btergm-style memory terms in a formula (`EdgeStability`/`PersistentEdge`/`NewEdge` refused, kept as descriptives).
- Entry-point ergonomics mirror `fit_ergm`: any term collection, a bare term, swapped arguments (the panel in the second OR third slot, or in several) and a single network are `ArgumentError`s in words (`stergm` has eight extra methods that only throw; `Test.detect_ambiguities(TERGM)` must stay empty — the methods whose first argument is `AbstractVector{<:Network}` exist solely to disambiguate against the entry point).
- Multi-column terms (`NodeFactor`, `NodeMix`, `Degree`/`IDegree`/`ODegree` ranges) are expanded at `STERGMModel` construction through ERGM's `_materialize`, never evaluated raw; `model.formula` holds one plain term per statistic and every hot path snapshots attributes per transition with `_materialized_tuple`. A `Tuple(model.formula.formation)` in a hot path is a regression (raw attribute terms allocate per row/toggle).
- `show` output is one line for `STERGM`/`STERGMModel` and carries `AIC: …, BIC: …` in `STERGMResult`'s header, matching `ERGMModel`/`ERGMResult`.
- The package uses `Float64` for all coefficients and statistics.
- Exports are declared at the top of the module. The StatsAPI verbs (`coef`, `stderror`, `vcov`, `confint`, `loglikelihood`, `aic`, `bic`, `nobs`, `dof`, `coeftable`) are re-exported so `coef(fit)` works with just `using TERGM`; they are the ONE `StatsAPI` binding, so this never collides with ERGM/Networks. Nothing else is re-exported: `Edges`, `network`, `load_dataset`, … come from `using ERGM, Networks`.
- Every export has a docstring with a runnable `# Example` on the 5-actor two-panel fixture of `test/runtests.jl` (or the `s50` panel), verified by executing them; the "Every export is documented with an example" testset pins the presence of the block for every name TERGM itself documents.
- CI/Documentation workflows never carry a literal sibling list: the clone step parses the `[sources]` tables of `Project.toml`/`docs/Project.toml` with `TOML` (after `setup-julia`, so `julia` is on the path) — pinned by the "Workflows derive their clone lists from [sources]" testset, which also asserts every `[sources]` path is a `../<Pkg>.jl` sibling (or `..` for the package itself in docs).
